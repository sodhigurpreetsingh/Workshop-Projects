✓ Safe — HTML escaped before rendering

What's the difference?

Vulnerable code
// User input inserted as raw HTML
const commentDiv = document.createElement('div');
commentDiv.innerHTML = userInput;
//          ^^^^^^^^^ parses & executes HTML
commentsContainer.appendChild(commentDiv);
Safe code
// User input inserted as plain text
const commentDiv = document.createElement('div');
commentDiv.textContent = userInput;
//          ^^^^^^^^^^^ treats everything as literal text
commentsContainer.appendChild(commentDiv);

One property change. innerHTML hands your string to the HTML parser — it sees <img onerror=...>, creates an image element, and fires the event handler. Your attacker's JavaScript now runs with full access to the page — cookies, localStorage, the DOM, network requests. textContent skips the parser entirely: every character is treated as a literal glyph to display. < stays <. No element is ever created. No handler ever fires.
